## Spec & Protocol

### Shipped
- **[spec#368](https://github.com/open-feature/spec/pull/368): Isolated API instances.** Adds spec section 1.8 for independent, non-singleton API instances, each with its own providers, context, hooks, and events, for use cases like micro-frontends, dependency injection, and test isolation. Resolves [spec#359](https://github.com/open-feature/spec/issues/359) (15 comments). Rollout tracked below.
- **[spec#375](https://github.com/open-feature/spec/pull/375): Shutdown must reset evaluation context and transaction context propagators (1.6.2).** The normative text previously listed only hooks, event handlers, and providers; some SDKs already reset the extra state and others did not. Follow-up issues filed in [js-sdk#1374](https://github.com/open-feature/js-sdk/issues/1374), [java-sdk#1926](https://github.com/open-feature/java-sdk/issues/1926), and [python-sdk#585](https://github.com/open-feature/python-sdk/issues/585), with a Python fix in review in [python-sdk#589](https://github.com/open-feature/python-sdk/pull/589).
- **[protocol#67](https://github.com/open-feature/protocol/pull/67): ADR-0008 event streams in the OFREP OpenAPI spec.** Adds `eventStreams` to bulk evaluation responses plus `flagConfigEtag` / `flagConfigLastModified` query parameters for SSE-triggered re-fetches, scoped to static-context providers; dynamic-context SSE is deferred to a follow-up ADR. Closes [protocol#62](https://github.com/open-feature/protocol/issues/62). The web provider implementation is in review in [js-sdk-contrib#1509](https://github.com/open-feature/js-sdk-contrib/pull/1509), alongside [js-sdk-contrib#1510](https://github.com/open-feature/js-sdk-contrib/pull/1510), which disables OFREP polling by default to make way for SSE.
- **[protocol#74](https://github.com/open-feature/protocol/pull/74): optional cache key prefix for OFREP local persistence.** Amends the local persistence ADR so providers expose an initialization option to prefix the cache key.

### Proposals to watch
- **[protocol#75](https://github.com/open-feature/protocol/pull/75): ADR 0009, cache-first local persistence for static-context OFREP providers.** Providers would load cached evaluations on startup so initial evaluations never return defaults, then refresh from the network, with a `cacheMode` option (`local-cache-first`, `network-first`, `disabled`). A matching ofrep-web implementation is open in [js-sdk-contrib#1508](https://github.com/open-feature/js-sdk-contrib/pull/1508).
- **[spec#373](https://github.com/open-feature/spec/issues/373): OTel hook cross-SDK inconsistencies** (6 comments, open). Catalogs where the OpenTelemetry hooks diverge from Appendix D and proposes a shared test harness modeled on flagd-testbed.
- **SDK and framework identity on client metadata.** The spec-level proposal ([spec#376](https://github.com/open-feature/spec/issues/376)) was closed in favor of a JS-first approach in [js-sdk#1375](https://github.com/open-feature/js-sdk/issues/1375), which would let providers and hooks tell `js-web` from `js-server` and React, Angular, or Nest without wrapper packages; implementation is in review in [js-sdk#1376](https://github.com/open-feature/js-sdk/pull/1376).

### Provider lifecycle race ([spec#365](https://github.com/open-feature/spec/issues/365))
SDKs are prototyping fixes for the race between SDK-managed provider state and provider-emitted events. [swift-sdk#114](https://github.com/open-feature/swift-sdk/pull/114) merged a breaking change that moves status tracking back into the provider, also addressing [swift-sdk#108](https://github.com/open-feature/swift-sdk/issues/108). Proofs of concept for an opt-in `StateManagingProvider` interface are open in [go-sdk#487](https://github.com/open-feature/go-sdk/pull/487) and [kotlin-sdk#230](https://github.com/open-feature/kotlin-sdk/pull/230).

## flagd & Operator

### flagd
- **[flagd#1931](https://github.com/open-feature/flagd/pull/1931): fix a memory leak from unbounded metrics cardinality**, caused by default OTel attributes that included remote peer and ephemeral port.
- **[flagd#1922](https://github.com/open-feature/flagd/pull/1922): experimental incremental gRPC sync updates** (8 comments). An opt-in `incrementalUpdates` source option scopes deletes to the flag sets in each payload, so multi-project backends do not clobber each other. A dedup follow-up is in review in [flagd#1940](https://github.com/open-feature/flagd/pull/1940).
- **[flagd#1945](https://github.com/open-feature/flagd/pull/1945): `intervalSeed` source option**, adding a deterministic offset to HTTP and blob polling to avoid thundering herds ([flagd#1944](https://github.com/open-feature/flagd/issues/1944)).
- **[flagd#1905](https://github.com/open-feature/flagd/pull/1905): preserve FeatureFlag metadata in Kubernetes sync** (13 comments), paired with the operator CRD change below.
- **Evaluator edge cases:** single-entry fractional operator support ([flagd#1935](https://github.com/open-feature/flagd/pull/1935)), object flags without a `defaultVariant` now fall back to the code default over RPC ([flagd#1925](https://github.com/open-feature/flagd/pull/1925), fixing [flagd#1913](https://github.com/open-feature/flagd/issues/1913)), and a zombie process fix when the metrics server fails ([flagd#1926](https://github.com/open-feature/flagd/pull/1926)). A coordinated flagd-testbed v3.6.2 update was filed across implementations ([flagd#1942](https://github.com/open-feature/flagd/issues/1942)), and [flagd-testbed#366](https://github.com/open-feature/flagd-testbed/issues/366) tracks migrating SDKs to the centralized evaluator testkit, starting with Python ([python-sdk-contrib#377](https://github.com/open-feature/python-sdk-contrib/pull/377)).
- **Discussion: [flagd#1927](https://github.com/open-feature/flagd/issues/1927): ISO 8601 timestamp support** (9 comments). Consensus is forming around a conversion operator approach that preserves JsonLogic compatibility, with an ADR suggested as the next step.
