## Spec & Protocol

### Proposals to watch

- **[protocol#73](https://github.com/open-feature/protocol/issues/73): OFREP write API for AI-tooling use cases.** Still early discussion on whether OFREP should define a standard CRUD surface for creating/updating/toggling flags, motivated by MCP-server and IDE-agent workflows.
- **Numeric coercion contract remains open:** [flagd#1996](https://github.com/open-feature/flagd/issues/1996), [flagd-schemas#224](https://github.com/open-feature/flagd-schemas/pull/224), and [dotnet-sdk-contrib#709](https://github.com/open-feature/dotnet-sdk-contrib/issues/709) are all still open two editions running; the schema PR caps numeric flag variants at the IEEE-754 safe-integer range (`feat!`, breaking for strict validators).
- **Hashing consistency (fractional evaluation CBOR rewrite) still in review:** [flagd#2011](https://github.com/open-feature/flagd/pull/2011) replaces string-concatenation Murmur3 hashing with deterministic CBOR encoding to support non-string bucketing inputs; a new ADR discussion for targeting metadata was also opened at [flagd#2013](https://github.com/open-feature/flagd/pull/2013).
- **Static-context client API hardening (multi-SDK):** [swift-sdk#123](https://github.com/open-feature/swift-sdk/issues/123) proposes restricting `track()` to the static-context client signature only, echoing similar lifecycle/context hardening merged this window in Kotlin ([kotlin-sdk#253](https://github.com/open-feature/kotlin-sdk/pull/253), fixing a provider/context race between `track()` and evaluation) and in progress in Dart ([dart-server-sdk#121](https://github.com/open-feature/dart-server-sdk/pull/121) tracking v0.9 conformance).
