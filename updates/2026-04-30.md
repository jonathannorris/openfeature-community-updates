## Spec & Protocol

### Shipped
- **[protocol#75](https://github.com/open-feature/protocol/pull/75): ADR 0009, cache-first local persistence for static-context providers.** On startup, OFREP static-context providers load cached evaluations immediately so the first evaluations do not fall back to defaults, then refresh from the network in parallel. Adds a `cacheMode` option (`local-cache-first` by default, plus `network-first` and `disabled`) mapped onto the `PROVIDER_READY` and `PROVIDER_CONFIGURATION_CHANGED` lifecycle.
- **[protocol#69](https://github.com/open-feature/protocol/pull/69): ADR 0010, disable default polling for static-context providers.** Providers should re-fetch on initialization, context change, app foreground or page visibility, and SSE push; timer-based polling stays available but becomes opt-in. The motivation is sticky bucketing and mobile resource use, and most vendor client SDKs already avoid timer polling by default.
- **[protocol#77](https://github.com/open-feature/protocol/pull/77): ADRs 0008, 0009, and 0010 marked accepted,** which together with SSE for bulk evaluation changes (ADR 0008) define the next generation of OFREP client behavior. Implementation interest is already showing up, e.g. a contributor picking up SSE support in the Go OFREP provider ([go-sdk-contrib#852](https://github.com/open-feature/go-sdk-contrib/issues/852)).
- **[spec#367](https://github.com/open-feature/spec/pull/367): Update status before emitting events.** SDKs must now update provider status before running event handlers, so a `PROVIDER_READY` handler never sees a provider that is still officially `NOT_READY` or `ERROR`. Go has a follow-up in review, [go-sdk#494](https://github.com/open-feature/go-sdk/pull/494) (from [go-sdk#493](https://github.com/open-feature/go-sdk/issues/493)).

### Proposals to watch
- **[spec#380](https://github.com/open-feature/spec/pull/380): Provider state race** (open). Moves provider status back into the provider interface, tightens ordering and atomicity guarantees, and adds a migration appendix, with proof-of-concept PRs in Go, Java, and JS. Addresses the long-running multi-threaded race in [spec#365](https://github.com/open-feature/spec/issues/365). Kotlin is already exploring the same direction with a state-managing provider and legacy adaptor ([kotlin-sdk#241](https://github.com/open-feature/kotlin-sdk/pull/241)).
- **[spec#382](https://github.com/open-feature/spec/pull/382): Clarify evaluation vs. resolution details** (open). A docs-only clarification of why both structures exist, with no requirement changes.

## Cross-SDK initiatives

### Isolated API instances
The spec now allows independent, non-singleton OpenFeature API instances, each with its own providers, context, hooks, and events, aimed at micro-frontends, DI frameworks, and testing. Tracking issues were filed per SDK (e.g. [java-sdk#1925](https://github.com/open-feature/java-sdk/issues/1925), [python-sdk#584](https://github.com/open-feature/python-sdk/issues/584)).

**In flight:** [java-sdk#1928](https://github.com/open-feature/java-sdk/pull/1928) · [go-sdk#492](https://github.com/open-feature/go-sdk/pull/492) · [php-sdk#171](https://github.com/open-feature/php-sdk/pull/171) · [kotlin-sdk#243](https://github.com/open-feature/kotlin-sdk/pull/243).

### Custom operator conformance
Driven by [flagd#1950](https://github.com/open-feature/flagd/pull/1950) (in review, fixes [flagd#1942](https://github.com/open-feature/flagd/issues/1942)), which would accept a `v` prefix in `sem_ver`, return `null` on errors in `sem_ver`, `ends_with`, and `fractional`, and fix the `fractional` fallback when total weight is zero. Companion test changes already landed in [flagd-testbed#369](https://github.com/open-feature/flagd-testbed/pull/369). Separately, [flagd#1949](https://github.com/open-feature/flagd/pull/1949) aligned missing or `null` targeting key handling in the fractional evaluator ([flagd#1948](https://github.com/open-feature/flagd/issues/1948)).

**Provider PRs:** [java-sdk-contrib#1778](https://github.com/open-feature/java-sdk-contrib/pull/1778) · [js-sdk-contrib#1519](https://github.com/open-feature/js-sdk-contrib/pull/1519) · [dotnet-sdk-contrib#635](https://github.com/open-feature/dotnet-sdk-contrib/pull/635) · [python-sdk-contrib#386](https://github.com/open-feature/python-sdk-contrib/pull/386) · [go-sdk-contrib#874](https://github.com/open-feature/go-sdk-contrib/pull/874).
