# OpenFeature Community Update: Aug 13 to Aug 27, 2026

_A biweekly digest of the most notable pull requests, issues, and discussions across the [open-feature](https://github.com/open-feature) org._

## TL;DR

- **Provider conformance is becoming a shared, reportable contract:** [spec#423](https://github.com/open-feature/spec/pull/423) proposes experimental Appendix F, with a machine-readable report schema in [spec#425](https://github.com/open-feature/spec/pull/425) and implementations across four SDK-contrib repositories.
- **OFREP gained a shipped push channel:** [flagd#2012](https://github.com/open-feature/flagd/pull/2012) adds an SSE server for OFREP endpoints.
- **The flagd retry-alignment work has its first landed fixes:** [js-sdk-contrib#1603](https://github.com/open-feature/js-sdk-contrib/pull/1603) and [java-sdk-contrib#1835](https://github.com/open-feature/java-sdk-contrib/pull/1835) correct the grace-period and backoff defaults, with other SDKs still tracking the change.
- **Dart's beta promotion is being hardened for release:** [dart-server-sdk#149](https://github.com/open-feature/dart-server-sdk/pull/149) closes lifecycle, cleanup, and publication blockers around the new client.
- **Experimentation design is getting sharper boundaries:** [spec#371](https://github.com/open-feature/spec/issues/371) proposes an evaluation-metrics hook, while discussion distinguishes evaluation telemetry from actual experiment exposure.

## Spec & Protocol
### Shipped

- **The legacy flagd evaluation API is now formally deprecated:** [flagd-schemas#227](https://github.com/open-feature/flagd-schemas/pull/227) deprecates `flagd/evaluation/v1`, completing the schema-side step behind the v2 migration already landing in providers.

### Proposals to watch

- **Provider conformance has a concrete specification home:** [spec#423](https://github.com/open-feature/spec/pull/423) adds an experimental, non-normative Appendix F with shared Gherkin scenarios, canonical flags, and a control API for testing providers against real backends.
- **Conformance publication is now a design discussion:** [spec#424](https://github.com/open-feature/spec/issues/424) considers how providers should publish reports that are comparable, provenance-backed, and discoverable without requiring OpenFeature to run vendor backends.
- **Experimentation support is being scoped around existing primitives:** [spec#371](https://github.com/open-feature/spec/issues/371) proposes counts by flag, reason, targeting key, and variant through an official hook; [spec#370](https://github.com/open-feature/spec/issues/370) explores standardized context fields and grouping multiple flags under one experiment. Recent discussion emphasizes that evaluation counts are not automatically exposure counts.

## Provider conformance rollout

The cross-language effort tracked by [spec#417](https://github.com/open-feature/spec/issues/417) moved from an open question to a working set of shared artifacts and runners.

- **In flight:** [spec#425](https://github.com/open-feature/spec/pull/425) defines a report schema with per-scenario results and four distinct outcomes, including `not-declared` and `not-applicable`, rather than a misleading aggregate score.
- **Language implementations:** Go is adding the suite and emitter in [go-sdk-contrib#940](https://github.com/open-feature/go-sdk-contrib/pull/940) and [#944](https://github.com/open-feature/go-sdk-contrib/pull/944); JavaScript in [js-sdk-contrib#1606](https://github.com/open-feature/js-sdk-contrib/pull/1606) and [#1610](https://github.com/open-feature/js-sdk-contrib/pull/1610); Python in [python-sdk-contrib#409](https://github.com/open-feature/python-sdk-contrib/pull/409) and [#413](https://github.com/open-feature/python-sdk-contrib/pull/413); and Java in [java-sdk-contrib#1837](https://github.com/open-feature/java-sdk-contrib/pull/1837), [#1838](https://github.com/open-feature/java-sdk-contrib/pull/1838), and [#1841](https://github.com/open-feature/java-sdk-contrib/pull/1841).
- **Early results are already useful:** the Java report emitter records 28 passed and one `not-declared` scenario for both flagd RPC and in-process configurations, making the missing strict numeric typing capability explicit instead of counting it as a pass. OFREP coverage is being wired up in [go-sdk-contrib#942](https://github.com/open-feature/go-sdk-contrib/pull/942), [java-sdk-contrib#1840](https://github.com/open-feature/java-sdk-contrib/pull/1840), [js-sdk-contrib#1612](https://github.com/open-feature/js-sdk-contrib/pull/1612), and [python-sdk-contrib#414](https://github.com/open-feature/python-sdk-contrib/pull/414).

## flagd & Operator
### flagd

- **OFREP push updates shipped:** [flagd#2012](https://github.com/open-feature/flagd/pull/2012) adds an SSE server using the ADR-0008 wire format, with `/ofrep/v1/sse` as the initial endpoint.
- **Retry timing is now less noisy in two SDKs:** [js-sdk-contrib#1603](https://github.com/open-feature/js-sdk-contrib/pull/1603) and [java-sdk-contrib#1835](https://github.com/open-feature/java-sdk-contrib/pull/1835) landed the default grace-period and maximum-backoff corrections prompted by [flagd#2027](https://github.com/open-feature/flagd/issues/2027). Go, Python, and .NET remain in the coordinated follow-up tracked by [go-sdk-contrib#936](https://github.com/open-feature/go-sdk-contrib/issues/936), [python-sdk-contrib#408](https://github.com/open-feature/python-sdk-contrib/issues/408), and [dotnet-sdk-contrib#730](https://github.com/open-feature/dotnet-sdk-contrib/issues/730).

### Operator

- **Controller-manager privileges are being reduced:** [open-feature-operator#855](https://github.com/open-feature/open-feature-operator/pull/855) proposes dropping all Linux capabilities from the controller-manager.

## SDKs & Providers

- **Dart's static-context client is being prepared for beta publication:** [dart-server-sdk#149](https://github.com/open-feature/dart-server-sdk/pull/149) hardens initialization, reconciliation, cancellation, shutdown cleanup, timeout quarantine, partial-failure rollback, hook handling, and independent Release Please publication.
- **C++ detailed evaluation is now shipped:** [cpp-sdk#130](https://github.com/open-feature/cpp-sdk/pull/130) adds detailed flag evaluation, following the options and context propagation work that landed alongside it.
- **The ConfigCat provider package rename landed as a breaking change:** [dotnet-sdk-contrib#727](https://github.com/open-feature/dotnet-sdk-contrib/pull/727) moves the package from `OpenFeature.Contrib.Providers.ConfigCat` to `OpenFeature.Providers.ConfigCat`.
