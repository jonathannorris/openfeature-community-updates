# OpenFeature Community Update: Mar 19 to Apr 2, 2026

_A biweekly digest of the most notable pull requests, issues, and discussions across the [open-feature](https://github.com/open-feature) org._

## TL;DR

- **KubeCon EU 2026 in Amsterdam produced a roadmap's worth of issues.** The recap post ([openfeature.dev#1359](https://github.com/open-feature/openfeature.dev/pull/1359)) summarizes six in-person discussions, and their action items were filed as new issues across `spec`, `protocol`, `flagd`, and `openfeature.dev` ([openfeature.dev#1363](https://github.com/open-feature/openfeature.dev/pull/1363)).
- **High-precision and nested `fractional` bucketing shipped in flagd and all five flagd provider languages** ([flagd#1909](https://github.com/open-feature/flagd/pull/1909)), a breaking change validated by a shared testbed suite.
- **Experimentation and OTel proposals opened in the spec:** standardized experiment context ([spec#370](https://github.com/open-feature/spec/issues/370)), an official evaluation metrics hook ([spec#371](https://github.com/open-feature/spec/issues/371)), and native SDK telemetry ([spec#372](https://github.com/open-feature/spec/issues/372)).
- **OFREP's road to 1.0 got a new batch of work items:** tracking, gRPC, routing headers, and a flag write API ([protocol#70](https://github.com/open-feature/protocol/issues/70) through [protocol#73](https://github.com/open-feature/protocol/issues/73)), plus ADR 0010 on default polling ([protocol#69](https://github.com/open-feature/protocol/pull/69)).
- **SDK highlights:** type-safe flag keys in the JS SDK ([js-sdk#1349](https://github.com/open-feature/js-sdk/pull/1349)), tracking in Python ([python-sdk#564](https://github.com/open-feature/python-sdk/pull/564)), and in-process evaluation for the Go GO Feature Flag provider ([go-sdk-contrib#851](https://github.com/open-feature/go-sdk-contrib/pull/851)).

## KubeCon + CloudNativeCon Europe 2026

OpenFeature previewed its schedule ahead of the event ([openfeature.dev#1347](https://github.com/open-feature/openfeature.dev/pull/1347)) and published a recap afterwards ([openfeature.dev#1359](https://github.com/open-feature/openfeature.dev/pull/1359)). The project had three sessions (a Maintainer Summit talk on secure package pipelines, the maintainer track update covering the MCP server, the flag-cleanup GitHub Action, and stable OFREP, and an OpenFeature plus OpenTelemetry demo with 18 PlayStation Move controllers) along with a Project Pavilion kiosk.

The more lasting output is six in-person discussions, each turned into tracked issues ([openfeature.dev#1363](https://github.com/open-feature/openfeature.dev/pull/1363)):

- **Experimentation:** [spec#370](https://github.com/open-feature/spec/issues/370), [spec#371](https://github.com/open-feature/spec/issues/371), [protocol#71](https://github.com/open-feature/protocol/issues/71), and clearer website messaging ([openfeature.dev#1362](https://github.com/open-feature/openfeature.dev/issues/1362)).
- **OFREP:** [protocol#70](https://github.com/open-feature/protocol/issues/70), [protocol#71](https://github.com/open-feature/protocol/issues/71), [protocol#72](https://github.com/open-feature/protocol/issues/72), with a stated target of OFREP 1.0 in Q2 2026.
- **flagd:** benchmarking and CI performance gating ([flagd#1915](https://github.com/open-feature/flagd/issues/1915)), case-insensitive matching ([flagd#1916](https://github.com/open-feature/flagd/issues/1916)), and a push toward a v1.0 milestone with defined evaluation test cases to reduce cross-language drift.
- **OTel observability:** native telemetry in SDKs ([spec#372](https://github.com/open-feature/spec/issues/372)) and more participation in the OTel feature flag semantic conventions SIG.
- **AI workflows:** a standard way for tools to create and manage flags ([protocol#73](https://github.com/open-feature/protocol/issues/73)).
- **Technical Committee:** consensus to grow the TC from three to at least five members.

## Spec & Protocol

### Proposals to watch
- **[spec#370](https://github.com/open-feature/spec/issues/370): Experimentation support.** Explores well-known context fields beyond the targeting key (browser, geo, device) and a standard way to group flags under a shared experiment ID.
- **[spec#371](https://github.com/open-feature/spec/issues/371): Official evaluation metrics hook.** Basic per-flag, per-reason evaluation metrics that analytics vendors could consume, published as a hook rather than new API surface.
- **[spec#372](https://github.com/open-feature/spec/issues/372): Native OTel telemetry in SDKs vs hooks.** Whether traces and metrics should be built into SDKs instead of requiring separate hook setup.
- **[protocol#69](https://github.com/open-feature/protocol/pull/69): ADR 0010, disable default polling for static-context providers.** Opened at the start of the window; proposes that providers re-fetch on init, context change, foreground/visibility, and SSE push, with timer polling opt-in. It was merged on Apr 23, after this window.
- **New OFREP issues:** a targeting-key hash header for routing and session affinity ([protocol#70](https://github.com/open-feature/protocol/issues/70)) · a tracking/event endpoint ([protocol#71](https://github.com/open-feature/protocol/issues/71)) · gRPC definitions ([protocol#72](https://github.com/open-feature/protocol/issues/72)) · a flag management/write API ([protocol#73](https://github.com/open-feature/protocol/issues/73)).

## High-precision and nested fractional bucketing

A coordinated rollout across flagd and every flagd provider. `fractional` now supports total weights up to max-int32 (1/max-int32 resolution) and computed variants and weights via nested JSONLogic. Umbrella issues: [flagd#1903](https://github.com/open-feature/flagd/issues/1903) (high resolution) and [flagd#1676](https://github.com/open-feature/flagd/issues/1676) (nested arguments), both closed Apr 1.

**Shipped:** [flagd#1909](https://github.com/open-feature/flagd/pull/1909) · [go-sdk-contrib#866](https://github.com/open-feature/go-sdk-contrib/pull/866) · [java-sdk-contrib#1740](https://github.com/open-feature/java-sdk-contrib/pull/1740) · [js-sdk-contrib#1501](https://github.com/open-feature/js-sdk-contrib/pull/1501) · [python-sdk-contrib#373](https://github.com/open-feature/python-sdk-contrib/pull/373) · [dotnet-sdk-contrib#622](https://github.com/open-feature/dotnet-sdk-contrib/pull/622).

**Schema and tests:** non-string and nested fractional variants ([flagd-schemas#207](https://github.com/open-feature/flagd-schemas/pull/207)) and a minimum-weight constraint with negative-weight clamping ([flagd-schemas#209](https://github.com/open-feature/flagd-schemas/pull/209)); testbed scenarios for nested weights and fractional as a condition ([flagd-testbed#352](https://github.com/open-feature/flagd-testbed/pull/352), [flagd-testbed#354](https://github.com/open-feature/flagd-testbed/pull/354), [flagd-testbed#357](https://github.com/open-feature/flagd-testbed/pull/357)). The Rust/WASM evaluator has a matching fix open ([flagd-evaluator#44](https://github.com/open-feature/flagd-evaluator/pull/44)).
