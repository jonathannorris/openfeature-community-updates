# OpenFeature Community Update: Jul 23 to Aug 6, 2026

## TL;DR

- **flagd SSE for OFREP:** [flagd#2012](https://github.com/open-feature/flagd/pull/2012) proposes a full ADR-0008-compliant SSE push endpoint (`/ofrep/v1/sse`) for flagd, enabling real-time flag updates over the OFREP protocol without polling.

## Cross-SDK: Hashing Consistency and Numeric Coercion

Two related correctness initiatives are in motion this window:

**Hashing consistency (fractional evaluation CBOR rewrite):**

- **[flagd#2011](https://github.com/open-feature/flagd/pull/2011):** Replaces string-concatenation Murmur3 hashing with deterministic CBOR encoding (`fxamacker/cbor/v2`), enabling non-string explicit bucketing inputs (numbers, booleans, maps, arrays) and consistent cross-platform hashing. Implements the `fractional-non-string-rand-units` ADR. In review.
- **[go-sdk-contrib#932](https://github.com/open-feature/go-sdk-contrib/pull/932):** Relaxes Gherkin step regex and removes a spurious `"null"`-to-nil coercion to support complex hashing input fixtures introduced by flagd#2011. Prerequisite for merging the flagd core change. In review.

**Numeric coercion contract:**

- **[flagd#1996](https://github.com/open-feature/flagd/pull/1996):** Implements the numeric coercion ADR in the flagd core evaluator; a second PR ([flagd#1995](https://github.com/open-feature/flagd/pull/1995)) tracks an alternative approach. Both are open.
- **[flagd-schemas#224](https://github.com/open-feature/flagd-schemas/pull/224):** Adds `minimum`/`maximum` bounds (`±9007199254740991`) to `numberVariants` in the JSON schema and regenerates `flags.json`. `feat!` because strict schema validators may now reject previously-accepted out-of-range configs. In review.
- **[flagd-testbed#379](https://github.com/open-feature/flagd-testbed/pull/379):** Adds ADR-conformant Gherkin scenarios under `@numeric-coercion-v2`. In review.
- **[dotnet-sdk-contrib#709](https://github.com/open-feature/dotnet-sdk-contrib/pull/709):** Early PR to adopt the numeric coercion contract in the .NET flagd provider. Open with 2 comments.

## flagd & Operator

### flagd

- **[flagd#2012](https://github.com/open-feature/flagd/pull/2012): SSE support for OFREP endpoints (new, Aug 4).** Adds a full Server-Sent Events push channel at `/ofrep/v1/sse`, implementing ADR-0008's wire format using the LaunchDarkly EventSource server. This complements the existing OFREP polling path and lets clients receive real-time flag updates. XL-sized PR (1,120 additions), currently in review.
- **[flagd#2013](https://github.com/open-feature/flagd/pull/2013): ADR for targeting metadata (new, Aug 5).** Proposes a new architecture decision record for how flagd should expose targeting metadata, allowing providers to surface rule-match context alongside evaluation results. 89 additions. In review.
- **[flagd#1997](https://github.com/open-feature/flagd/issues/1997): DISABLED-flag gap from 0.16.0 confirmed and resolved.** A community report revealed that the PHP flagd RPC provider was silently returning the language zero value (e.g., `false`) instead of the caller-supplied default for disabled flags, because v1 proto always sends a wire value. Maintainers confirmed the gap was missed during rollout, fixed it in `php-flagd-provider 1.1.1`, and committed to clarifying the 0.16.0 release notes with minimum provider version requirements. Go, Java, JS, Python, and .NET RPC providers were already correct.

### Operator

- **[open-feature-operator#853](https://github.com/open-feature/open-feature-operator/pull/853): Expose pod scheduling fields on the Flagd CRD (new, Aug 5).** Adds `nodeSelector`, `affinity`, `tolerations`, and `topologySpreadConstraints` as optional fields on `FlagdSpec`, all passed through to the generated Deployment's pod template. Fields are additive and default to unset, so existing resources are unaffected. Large PR (3,524 additions due to regenerated CRD and docs). In review.

## SDKs & Providers

- **[go-sdk#528](https://github.com/open-feature/go-sdk/pull/528) (open): Allow binding a provider to multiple domains.** Fixes the Go SDK so the same initialized provider instance can be bound as both the default provider and to one or more named domains, rather than re-initializing on each bind. Part of the spec v0.9.0 compliance wave. In review.
- **[rust-sdk#140](https://github.com/open-feature/rust-sdk/pull/140) (open): Implement HookData (spec 4.6).** Adds a per-hook, per-evaluation key-value store (`HookData`) on `HookContext`, letting a hook carry state across its own before/after/finally stages (e.g., open a span in `before`, close in `finally`). Each hook instance gets isolated storage. Closes #102.
- **[js-sdk-contrib#1591](https://github.com/open-feature/js-sdk-contrib/pull/1591) (merged, Aug 2): Flagsmith JS provider major overhaul.** Breaking: migrates the peer dependency from the unscoped `flagsmith` package (stopped at 10.x) to `@flagsmith/flagsmith` `^12.1.2`. Adds experimental tracking (`track()` with spec §6 surface), honest resolution reasons (`DEFAULT`, `DISABLED`, `CACHED`, `TARGETING_MATCH`), variant and experiment metadata in `flagMetadata`, and `onClose()` cleanup. Also fixes `resolveBooleanEvaluation` returning `false` instead of the caller's `defaultValue` for missing flags.
- **[js-sdk-contrib#1597](https://github.com/open-feature/js-sdk-contrib/pull/1597) (merged, Aug 5): Fix OFREP web provider SSE reconnect when polling is disabled.** When `pollInterval` is negative (disabling polling), the SSE connection was not reconnecting on drop. Fixed; `ofrep-web-provider 0.4.3` release follows ([js-sdk-contrib#1599](https://github.com/open-feature/js-sdk-contrib/pull/1599)).
- **[python-sdk-contrib#405](https://github.com/open-feature/python-sdk-contrib/pull/405) (merged, Aug 1) + [#406](https://github.com/open-feature/python-sdk-contrib/pull/406):** Fixes the flagd Python provider logging expected sync-stream recycles (10-minute deadline) at WARNING instead of DEBUG, cutting logspam; `openfeature-provider-flagd 0.5.2` released.
- **[go-sdk-contrib#927](https://github.com/open-feature/go-sdk-contrib/pull/927) (merged, Jul 31): Fix from-env provider complex criteria comparison.** Safely compares complex criteria values in the from-env provider, fixing a correctness bug when non-scalar values were used in targeting rules.
- **New ecosystem entries:** Unleash submitted provider listings for Python ([#1423](https://github.com/open-feature/openfeature.dev/pull/1423)), PHP ([#1424](https://github.com/open-feature/openfeature.dev/pull/1424)), Android ([#1425](https://github.com/open-feature/openfeature.dev/pull/1425)), Rust ([#1426](https://github.com/open-feature/openfeature.dev/pull/1426)), Ruby ([#1427](https://github.com/open-feature/openfeature.dev/pull/1427)), Node ([#1428](https://github.com/open-feature/openfeature.dev/pull/1428)), and Swift ([#1432](https://github.com/open-feature/openfeature.dev/pull/1432)) in a coordinated batch. Rollgate JS provider ([openfeature.dev#1421](https://github.com/open-feature/openfeature.dev/pull/1421)) is still awaiting review.

## Community & Governance

- **[community#565](https://github.com/open-feature/community/issues/565): flagctl CLI for flagd GitOps workflows.** Rasul Khan is requesting feedback on `flagctl` (Apache 2.0), a community-built CLI for ergonomic management of flagd flag files in GitOps pipelines. Key features include `launch` (progressive ramp with spec-compliant bucketing), `target` (ordered rule targeting with overlap analysis), `deprecate` (2-stage deprecation keeping `state: ENABLED`), and `delete` (scans TypeScript/Go/Python/Java/C#/PHP/Rust source for live references before blocking deletion). No maintainer response yet; worth evaluating for inclusion in community tooling.
- **[dotnet-sdk-contrib#154](https://github.com/open-feature/dotnet-sdk-contrib/issues/154): NuGet package naming inconsistencies (13 comments, very active).** A long-running discussion about whether `.Contrib` should be dropped from package names (e.g., `OpenFeature.Providers.ConfigCat` instead of `OpenFeature.Contrib.Providers.ConfigCat`), following OpenTelemetry's convention. The ConfigCat rename ([dotnet-sdk-contrib#713](https://github.com/open-feature/dotnet-sdk-contrib/pull/713)) is the first sub-issue to move forward. Other providers remain on the backlog.
