# OpenFeature Community Update: Apr 30 to May 14, 2026

_A biweekly digest of the most notable pull requests, issues, and discussions across the [open-feature](https://github.com/open-feature) org._

## TL;DR

- **flagd custom operator conformance fixes landed everywhere at once:** flagd plus the Java, JS, .NET, Python, and Go in-process providers now agree on `sem_ver`, `ends_with`, and `fractional` edge cases ([flagd#1950](https://github.com/open-feature/flagd/pull/1950)).
- **The OFREP web provider got local persistence and drops polling by default** to make way for SSE ([js-sdk-contrib#1508](https://github.com/open-feature/js-sdk-contrib/pull/1508), [js-sdk-contrib#1510](https://github.com/open-feature/js-sdk-contrib/pull/1510)).
- **The .NET SDK added isolated API instances**, letting tests, multi-tenant apps, and DI setups run independent OpenFeature APIs ([dotnet-sdk#740](https://github.com/open-feature/dotnet-sdk/pull/740)).
- **Java flagd moved to a maintained, faster JSON Logic library** with optional targeting-rule pre-compilation ([java-sdk-contrib#1786](https://github.com/open-feature/java-sdk-contrib/pull/1786), [java-sdk-contrib#1791](https://github.com/open-feature/java-sdk-contrib/pull/1791)).
- **An OTel Demo maintainer opened a debate on flagd EventStream telemetry:** should `DEADLINE_EXCEEDED` on long-lived streams count as an error ([flagd#1959](https://github.com/open-feature/flagd/issues/1959), 10 comments)?

## Spec & Protocol

The spec and protocol repos were quiet this period; the action was in SDKs catching up to existing requirements.

### Shipped (spec conformance in SDKs)
- **[go-sdk#494](https://github.com/open-feature/go-sdk/pull/494): Update provider status before invoking API-level handlers.** Global event handlers previously saw a stale status; the fix brings Go in line with requirement 5.3.5 (fixes [go-sdk#493](https://github.com/open-feature/go-sdk/issues/493)).
- **[kotlin-sdk#239](https://github.com/open-feature/kotlin-sdk/pull/239): Remove the deprecated `ProviderNotReady` event** (breaking). `NOT_READY` is a status, not a spec event, and `PROVIDER_ERROR` now carries structured details.

### Proposals to watch
- **[spec#373](https://github.com/open-feature/spec/issues/373): OTel hook cross-SDK inconsistencies** (6 comments, open). Catalogues where the contrib OpenTelemetry hooks diverge from Appendix D and proposes a shared test harness modelled on flagd-testbed; it picked up a new comment in the window.
- **[java-sdk#1936](https://github.com/open-feature/java-sdk/pull/1936): Shutdown clears hooks, evaluation context, and the transaction context propagator** per spec 1.6.2 (open at window end).
- **[go-sdk#495](https://github.com/open-feature/go-sdk/issues/495): Provider lifecycle calls may occur in invalid order.** A new bug report showing `Init` can run after `openfeature.Shutdown()`, and `Shutdown` can reach a provider that never got `Init`.

## flagd in-process evaluation consistency

Part of the long-running effort to make every in-process flagd provider return identical results for the same flag configuration ([flagd#1904](https://github.com/open-feature/flagd/issues/1904), closed May 1, with the testbed bump tracked in [flagd#1942](https://github.com/open-feature/flagd/issues/1942)). The fixes add `V`-prefix support to `sem_ver`, return `null` on errors from `sem_ver`, `ends_with`, and `fractional` so the default variant applies, and correct `fractional` fallback when total weight is zero.

**Shipped:** [flagd#1950](https://github.com/open-feature/flagd/pull/1950) · [java-sdk-contrib#1778](https://github.com/open-feature/java-sdk-contrib/pull/1778) · [js-sdk-contrib#1519](https://github.com/open-feature/js-sdk-contrib/pull/1519) · [dotnet-sdk-contrib#635](https://github.com/open-feature/dotnet-sdk-contrib/pull/635) · [python-sdk-contrib#386](https://github.com/open-feature/python-sdk-contrib/pull/386) · [go-sdk-contrib#874](https://github.com/open-feature/go-sdk-contrib/pull/874), plus [flagd-testbed#372](https://github.com/open-feature/flagd-testbed/pull/372) and the jsonlogic `and`/`or` fix in [flagd#1957](https://github.com/open-feature/flagd/pull/1957).

**Also joining:** the C++ provider implemented all flagd-specific operators (`starts_with`, `ends_with`, `semver`, `fractional` with high-precision bucketing) in [cpp-sdk-contrib#92](https://github.com/open-feature/cpp-sdk-contrib/pull/92). Next up is [flagd-testbed#374](https://github.com/open-feature/flagd-testbed/issues/374), smoke tests for the standard JSON Logic operators.

## flagd & Operator

### flagd
- **[flagd#1959](https://github.com/open-feature/flagd/issues/1959): EventStream `DEADLINE_EXCEEDED` shouldn't be an error** (10 comments, open). The OTel Demo sees 10 to 30 minute EventStream spans marked as errors; the thread is weighing how long-lived streams should be represented in traces. A related report, [js-sdk-contrib#1522](https://github.com/open-feature/js-sdk-contrib/issues/1522), notes the v2 EventStream not clearing trace context.
- **Stream reconnect backoff:** Java's RPC mode now applies the spec'd backoff to avoid tight reconnect loops caused by immediate proxy errors ([java-sdk-contrib#1789](https://github.com/open-feature/java-sdk-contrib/pull/1789)); a matching Python fix is open ([python-sdk-contrib#391](https://github.com/open-feature/python-sdk-contrib/pull/391)).
- **[java-sdk-contrib#1786](https://github.com/open-feature/java-sdk-contrib/pull/1786): switch to the `io.github.gzsombor` JSON Logic fork** after the previous library's maintainer went unresponsive, with large speed and memory gains. [java-sdk-contrib#1791](https://github.com/open-feature/java-sdk-contrib/pull/1791) follows with a `CompileTargetingMode` (`ENABLED`, `DISABLED`, `AUTO`) that pre-compiles rules when `jdk.compiler` is available.
- **[flagd#1956](https://github.com/open-feature/flagd/pull/1956):** `OTEL_SERVICE_NAME` and `OTEL_RESOURCE_ATTRIBUTES` now override flagd's service name and version (fixes [flagd#1938](https://github.com/open-feature/flagd/issues/1938)).
- **In review:** custom headers for HTTP and gRPC sync providers, for gateways and service meshes that require routing or tenant headers ([flagd#1960](https://github.com/open-feature/flagd/pull/1960)); a `FILE` resolver for the .NET flagd provider ([dotnet-sdk-contrib#647](https://github.com/open-feature/dotnet-sdk-contrib/pull/647)).
- **Licensing hygiene:** a `LICENSE` was added to the protobuf BSR module root so FOSSA stops flagging the generated Go SDKs as unlicensed ([flagd-schemas#212](https://github.com/open-feature/flagd-schemas/pull/212), from [flagd-schemas#211](https://github.com/open-feature/flagd-schemas/issues/211)); the same problem was reported for the Java flagd Maven artifacts ([java-sdk-contrib#1784](https://github.com/open-feature/java-sdk-contrib/issues/1784)).

### Operator
- **[open-feature-operator#802](https://github.com/open-feature/open-feature-operator/pull/802): `valueFrom` support in `envVars`** for `FeatureFlagSource` and `InProcessConfiguration`, so sidecar config can come from Secrets or ConfigMaps.
- **[open-feature-operator#841](https://github.com/open-feature/open-feature-operator/issues/841): the v0.9.1 chart's `kubeVersion: >=1.29.0` breaks installs on EKS, GKE, and AKS** because their version strings carry pre-release suffixes; a fix is open in [open-feature-operator#842](https://github.com/open-feature/open-feature-operator/pull/842).
- [open-feature-operator#838](https://github.com/open-feature/open-feature-operator/pull/838) aligns `FeatureFlagSource` CRD defaults with the docs · standalone flagd deployments were reported to lack liveness/readiness probes ([open-feature-operator#837](https://github.com/open-feature/open-feature-operator/issues/837)).
