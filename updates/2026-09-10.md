# OpenFeature Community Update: Aug 27 to Sep 10, 2026

_A biweekly digest of the most notable pull requests, issues, and discussions across the [open-feature](https://github.com/open-feature) org._

## TL;DR

- **Provider conformance is moving from test execution toward public reporting:** [spec#424](https://github.com/open-feature/spec/issues/424) now focuses on comparable machine-readable reports for providers that OpenFeature cannot run directly.
- **The hook contract is getting an explicit after-hook rule:** [spec#428](https://github.com/open-feature/spec/pull/428) proposes a new requirement that an after-hook error returns the default value.
- **flagd expanded its serving and deployment surface:** [flagd#2037](https://github.com/open-feature/flagd/pull/2037) adds HTTP parity for `FetchAllFlags`, [flagd#2042](https://github.com/open-feature/flagd/pull/2042) migrates the gRPC handler to Connect, and [flagd#2039](https://github.com/open-feature/flagd/pull/2039) adds a FIPS 140-3 build mode.
- **The Dart static-context client reached beta publication:** [dart-server-sdk#156](https://github.com/open-feature/dart-server-sdk/pull/156) follows the beta promotion and final review work from the previous period.
- **The provider ecosystem keeps widening:** Featureflip's Python provider shipped in [openfeature.dev#1469](https://github.com/open-feature/openfeature.dev/pull/1469), while UseFlagly's Node.js provider and OFREP endpoint are being added in [openfeature.dev#1471](https://github.com/open-feature/openfeature.dev/pull/1471).

## Spec & Protocol
### Shipped

- **OFREP cache precedence is now documented:** [protocol#84](https://github.com/open-feature/protocol/pull/84) clarifies that `flagConfigEtag` controls the 200-versus-304 decision, while other cache headers must not downgrade a 200 response.

### Proposals to watch

- **After-hook failures would be explicitly abnormal execution:** [spec#428](https://github.com/open-feature/spec/pull/428) adds Requirement 4.4.8 so an error in an `after` hook returns the default value. The related discussion in [spec#427](https://github.com/open-feature/spec/issues/427) is deciding whether to add the new requirement or broaden 4.4.7, while keeping `error` and `finally` hook behavior distinct.

## Provider conformance rollout

The shared conformance suite and report schema covered in the previous edition now have a publication design discussion.

- **In flight:** [spec#424](https://github.com/open-feature/spec/issues/424) proposes reports that carry the TCK implementation, spec revision, conformance-asset digest, declared capabilities, and per-scenario outcomes. The design also addresses reports from vendor-hosted providers whose backends and credentials OpenFeature cannot execute.
- **Tracking work:** the Dart server SDK opened [dart-server-sdk#165](https://github.com/open-feature/dart-server-sdk/issues/165) for its v0.9 conformance report and external-provider validation, plus [dart-server-sdk#166](https://github.com/open-feature/dart-server-sdk/issues/166) for one shared contract suite against two independent providers.

## flagd & Operator
### flagd

- **File polling is configurable:** [flagd#2045](https://github.com/open-feature/flagd/pull/2045) replaces the hard-coded one-second interval, enabling downstream providers to expose an offline polling interval.
- **HTTP gained `FetchAllFlags` parity:** [flagd#2037](https://github.com/open-feature/flagd/pull/2037) adds the watcher and listener behavior over HTTP, including ETag and `Last-Modified` handling for flagd-to-flagd use cases.
- **The gRPC handler moved to Connect:** [flagd#2042](https://github.com/open-feature/flagd/pull/2042) is intended as a client-compatible replacement and removes the need for the earlier minimum-version settings.
- **Restricted deployments get a FIPS 140-3 mode:** [flagd#2039](https://github.com/open-feature/flagd/pull/2039) adds a `-fips` build for environments that require the newer Go FIPS capabilities.

## SDKs & Providers

- **Dart beta publication is complete:** [dart-server-sdk#156](https://github.com/open-feature/dart-server-sdk/pull/156) publishes `openfeature_dart_client_sdk` 0.0.1-beta.1 after the static-context beta promotion and review-gate fixes in [dart-server-sdk#148](https://github.com/open-feature/dart-server-sdk/pull/148).
- **Optimizely coverage is being added across JavaScript environments:** [js-sdk-contrib#1619](https://github.com/open-feature/js-sdk-contrib/pull/1619), [js-sdk-contrib#1620](https://github.com/open-feature/js-sdk-contrib/pull/1620), and [js-sdk-contrib#1621](https://github.com/open-feature/js-sdk-contrib/pull/1621) propose Node.js server, browser, and universal edge providers.
- **Provider-owned lifecycle events are still being aligned across SDKs:** [kotlin-sdk#262](https://github.com/open-feature/kotlin-sdk/pull/262) moves status tracking back to providers, while [dotnet-sdk#816](https://github.com/open-feature/dotnet-sdk/pull/816) allows providers to emit their own `PROVIDER_READY` and `PROVIDER_ERROR` events.
- **The Go SDK landed several evaluation-context correctness fixes:** [go-sdk#573](https://github.com/open-feature/go-sdk/pull/573) copies caller-owned hook hints, [go-sdk#569](https://github.com/open-feature/go-sdk/pull/569) merges before-hook context, and [go-sdk#565](https://github.com/open-feature/go-sdk/pull/565) coerces integer values for float evaluation in the in-memory provider.

## Community & Governance

- **The ecosystem directory is adding more provider options:** [openfeature.dev#1478](https://github.com/open-feature/openfeature.dev/pull/1478) proposes a Flagsmith Swift provider, [openfeature.dev#1476](https://github.com/open-feature/openfeature.dev/pull/1476) proposes Featureflip Go and Java providers, and [openfeature.dev#1475](https://github.com/open-feature/openfeature.dev/pull/1475) proposes Nona .NET and JavaScript providers.
