# OpenFeature Community Update: May 14 to May 28, 2026

_A biweekly digest of the most notable pull requests, issues, and discussions across the [open-feature](https://github.com/open-feature) org._

## TL;DR

- **flagd is changing how disabled flags evaluate.** The ADR landed ([flagd#1919](https://github.com/open-feature/flagd/pull/1919)): disabled flags become a successful evaluation with `reason=DISABLED` instead of a `FLAG_DISABLED` error, and a coordinated rollout across flagd and its providers is underway ([flagd#1965](https://github.com/open-feature/flagd/issues/1965)).
- **Multi-Provider and DISABLED:** a spec proposal would have all standard strategies fall through on `reason=DISABLED` the same way they do on `FLAG_NOT_FOUND` ([spec#386](https://github.com/open-feature/spec/pull/386), 12 comments).
- **Provider state ownership via events proposed** as a simpler fix for the long-running lifecycle race condition ([spec#385](https://github.com/open-feature/spec/pull/385)).
- **OFREP web provider gains SSE** for real-time flag change notifications ([js-sdk-contrib#1509](https://github.com/open-feature/js-sdk-contrib/pull/1509)).
- **Python SDK spec alignment:** non-blocking `set_provider()` plus `set_provider_and_wait()` ([python-sdk#595](https://github.com/open-feature/python-sdk/pull/595)) and isolated event handler dispatch ([python-sdk#599](https://github.com/open-feature/python-sdk/pull/599)).

## Spec & Protocol

### Proposals to watch
- **[spec#386](https://github.com/open-feature/spec/pull/386): Multi-Provider strategies skip providers returning `reason=DISABLED`** (12 comments, open). First Match and First Successful would skip a provider that reports a flag as intentionally off, and Comparison would exclude it. The PR notes that many providers (Flipt, Flagsmith, LaunchDarkly, GO Feature Flag, OFREP, and others) already return `reason=DISABLED`, and that without this change the flagd move below would silently break Multi-Provider fall-through.
- **[spec#385](https://github.com/open-feature/spec/pull/385): Provider state ownership via events** (open). Providers would emit their own lifecycle events (`PROVIDER_READY`, `PROVIDER_ERROR`, etc.) and the SDK would derive status from them, rather than firing synthetic events after `init()` returns. Positioned as a smaller alternative to the `getState()` approach in [spec#380](https://github.com/open-feature/spec/pull/380), resolving the race discussed in [spec#365](https://github.com/open-feature/spec/issues/365).
- **[spec#387](https://github.com/open-feature/spec/pull/387):** expands the example for requirement 1.3.3.1 (open, small clarification).

## Disabled flags as successful evaluations

The [flagd ADR](https://github.com/open-feature/flagd/pull/1919) (merged, fixes [flagd#1918](https://github.com/open-feature/flagd/issues/1918)) moves flagd from a `FLAG_DISABLED` error to a successful result with `reason=DISABLED`. Resolved values are unchanged, since callers still receive their default, so the break is only visible to consumers that inspect `reason` or `errorCode`, call flagd directly over gRPC or OFREP, or import `core/pkg/model`. Umbrella issue: [flagd#1965](https://github.com/open-feature/flagd/issues/1965).

## flagd & Operator

### flagd
- **[flagd#1960](https://github.com/open-feature/flagd/pull/1960): custom headers for sync providers.** HTTP and gRPC sync sources accept an optional `headers` map, sent as request headers or gRPC metadata, for gateways and service meshes that route on headers. Follow-up [flagd#1969](https://github.com/open-feature/flagd/pull/1969) bumps core and adds docs.
- **[java-sdk-contrib#1798](https://github.com/open-feature/java-sdk-contrib/pull/1798): validate `FLAGD_SYNC_PORT` before parsing.** Fixes a crash when Kubernetes service-link env injection sets that variable to a URL-like value in in-process mode ([java-sdk-contrib#1797](https://github.com/open-feature/java-sdk-contrib/issues/1797)).
- **[cpp-sdk-contrib#87](https://github.com/open-feature/cpp-sdk-contrib/pull/87): automatic gRPC sync reconnection** with backoff for the C++ flagd provider (closes [cpp-sdk-contrib#12](https://github.com/open-feature/cpp-sdk-contrib/issues/12)).

### Operator

## SDKs & Providers

- **[js-sdk-contrib#1509](https://github.com/open-feature/js-sdk-contrib/pull/1509): SSE event streams in the OFREP web provider.** Implements ADR-0008: the provider reads `eventStreams` from bulk evaluation responses, connects via `EventSource`, coalesces change events, and falls back to polling when SSE is unavailable.
- **Python SDK:** `set_provider()` is now non-blocking with a new `set_provider_and_wait()`, matching the other SDKs and avoiding worker timeouts when a provider hangs on init ([python-sdk#595](https://github.com/open-feature/python-sdk/pull/595), breaking, closes [python-sdk#594](https://github.com/open-feature/python-sdk/issues/594)); event handlers run outside the registry lock with per-handler error isolation per spec 5.2.5 ([python-sdk#599](https://github.com/open-feature/python-sdk/pull/599), for [python-sdk#596](https://github.com/open-feature/python-sdk/issues/596)). Both were open at window end and merged the following day.
- **Java SDK spec fixes:** domain-scoped client event handlers no longer disappear ([java-sdk#1922](https://github.com/open-feature/java-sdk/pull/1922), for [java-sdk#1919](https://github.com/open-feature/java-sdk/issues/1919)); `shutdown()` now clears hooks, evaluation context, and the transaction context propagator per spec 1.6.2 ([java-sdk#1936](https://github.com/open-feature/java-sdk/pull/1936)).
- **.NET:** DI registration now uses an isolated API instance instead of the global singleton, fixing a regression after the `OpenFeature.DependencyInjection` deprecation ([dotnet-sdk#760](https://github.com/open-feature/dotnet-sdk/pull/760), for [dotnet-sdk#759](https://github.com/open-feature/dotnet-sdk/issues/759)); tests moved to xUnit v3 and Microsoft Testing Platform v2 ([dotnet-sdk#681](https://github.com/open-feature/dotnet-sdk/pull/681)).
- **New and upgraded providers (open):** Unleash provider for .NET ([dotnet-sdk-contrib#652](https://github.com/open-feature/dotnet-sdk-contrib/pull/652)) · AOT compatibility for the .NET OFREP provider ([dotnet-sdk-contrib#651](https://github.com/open-feature/dotnet-sdk-contrib/pull/651)) · LaunchDarkly JS provider upgrade to 4.x ([js-sdk-contrib#1551](https://github.com/open-feature/js-sdk-contrib/pull/1551), breaking).
- **Smaller fixes:** C++ SDK shuts down the old provider when a replacement fails to initialize ([cpp-sdk#98](https://github.com/open-feature/cpp-sdk/pull/98)) · CLI-generated flag manifests end with a final newline ([cli#246](https://github.com/open-feature/cli/pull/246)) · GO Feature Flag WASM module bumped to 0.2.2 across JS, Java, and .NET providers ([js-sdk-contrib#1550](https://github.com/open-feature/js-sdk-contrib/pull/1550), [java-sdk-contrib#1796](https://github.com/open-feature/java-sdk-contrib/pull/1796), [dotnet-sdk-contrib#648](https://github.com/open-feature/dotnet-sdk-contrib/pull/648)).
