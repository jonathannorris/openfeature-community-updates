# OpenFeature Community Update: Sep 17 to Oct 1, 2026

_A biweekly digest of the most notable pull requests, issues, and discussions across the [open-feature](https://github.com/open-feature) org._

## TL;DR

- **The protocol now restores an optional targeting key:** [protocol#86](https://github.com/open-feature/protocol/pull/86) shipped the schema correction, with cache behavior for anonymous evaluations proposed in [protocol#87](https://github.com/open-feature/protocol/pull/87).
- **Provider conformance is moving toward an experimental TCK:** [spec#439](https://github.com/open-feature/spec/pull/439) defines capabilities, control APIs, and run-integrity checks for the shared suite.
- **Dart has moved from feature implementation to release evidence:** [dart-sdk#199](https://github.com/open-feature/dart-sdk/pull/199) promotes the client and server work to main, while [dart-sdk#117](https://github.com/open-feature/dart-sdk/issues/117) and [dart-sdk#121](https://github.com/open-feature/dart-sdk/issues/121) still track stable acceptance.
- **flagd added compressed OFREP responses and configurable tracing:** [flagd#2071](https://github.com/open-feature/flagd/pull/2071) and [flagd#2070](https://github.com/open-feature/flagd/pull/2070) are shipped, while [flagd#2077](https://github.com/open-feature/flagd/pull/2077) proposes bounding metric cardinality.
- **The provider ecosystem and a major Java integration both expanded:** [java-sdk-contrib#1868](https://github.com/open-feature/java-sdk-contrib/pull/1868) hardens the GO Feature Flag provider, and [openfeature.dev#1546](https://github.com/open-feature/openfeature.dev/pull/1546) adds more ConfigDirector integrations.

## Spec & Protocol
### Shipped

- **Missing targeting keys are valid evaluation context:** [protocol#86](https://github.com/open-feature/protocol/pull/86) removes the schema requirement and aligns the protocol with the OpenFeature specification.
- **After-hook failures now return the default:** [spec#428](https://github.com/open-feature/spec/pull/428) adds a dedicated conformance requirement for abnormal execution in an `after` hook.

### Proposals to watch

- **Anonymous cache behavior is being made explicit:** [protocol#87](https://github.com/open-feature/protocol/pull/87) proposes evaluating contexts without a targeting key normally but not persisting their results, unless an application supplies an identity-safe cache key.
- **A provider conformance TCK is under review:** [spec#439](https://github.com/open-feature/spec/pull/439), part of [spec#417](https://github.com/open-feature/spec/issues/417), describes an experimental shared suite with capability tags, a control API, extension rules, and checks that prevent incomplete or stale runs from appearing green.

## Multi-Provider

- **The informal Multi-Provider guidance could become a first-class specification:** [spec#437](https://github.com/open-feature/spec/issues/437) proposes numbered requirements and shared Gherkin coverage for initialization, status aggregation, evaluation strategies, shutdown, metadata, and per-child hook isolation.
- **In flight:** [go-sdk#604](https://github.com/open-feature/go-sdk/pull/604) closes event channels and shuts down providers that reached ready when a Multi-Provider initialization fails, addressing the leak tracked in [go-sdk#561](https://github.com/open-feature/go-sdk/issues/561).

## flagd & Operator
### flagd

- **OFREP evaluation responses can use gzip:** [flagd#2071](https://github.com/open-feature/flagd/pull/2071) compresses evaluation routes when requested, preserves the uncompressed SSE stream, and adds the required cache variation headers.
- **JSON evaluation tracing is configurable:** [flagd#2070](https://github.com/open-feature/flagd/pull/2070) allows a caller to override the global `TraceProvider`.
- **Metric cardinality protection is proposed:** [flagd#2077](https://github.com/open-feature/flagd/pull/2077) would collapse unknown evaluation paths into `other`, avoiding unbounded `http.route` series. A related request, [flagd#2020](https://github.com/open-feature/flagd/issues/2020), asks for flag set IDs in OTEL metrics.

### Operator

- **Digest-pinned proxy images still need a deployment fix:** [open-feature-operator#863](https://github.com/open-feature/open-feature-operator/issues/863) reports invalid Kubernetes version labels, and the in-flight fix [open-feature-operator#864](https://github.com/open-feature/open-feature-operator/pull/864) strips the digest and validates the resulting label without changing the image reference.

## SDKs & Providers

- **Dart’s v0.9 work is now an evidence and release-gating effort:** [dart-sdk#199](https://github.com/open-feature/dart-sdk/pull/199) promotes reconciliation and contract-v2 corrections, with [dart-sdk#198](https://github.com/open-feature/dart-sdk/pull/198) and [dart-sdk#197](https://github.com/open-feature/dart-sdk/pull/197) updating conformance evidence and migration documentation. Server lifecycle cleanup and readiness work landed in [dart-sdk#190](https://github.com/open-feature/dart-sdk/pull/190), but the parent release issues still mark stable acceptance as pending.
- **The GO Feature Flag Java provider was substantially refactored:** [java-sdk-contrib#1868](https://github.com/open-feature/java-sdk-contrib/pull/1868) aligns the integration with its provider specification, adds relay fallback, stale-state recovery, data collector configuration, and clearer event and error handling, with breaking cleanup of unused connection options.
- **Fractional evaluation is gaining cross-language hashing behavior:** [dotnet-sdk-contrib#748](https://github.com/open-feature/dotnet-sdk-contrib/pull/748) proposes canonical CBOR hashing and non-string bucketing attributes for the flagd provider.
- **OFREP web caching is following the targeting-key correction:** [js-sdk-contrib#1635](https://github.com/open-feature/js-sdk-contrib/pull/1635) proposes not persisting evaluations that have no targeting key.

## Community & Governance

- **The ecosystem directory is broadening its protocol and language coverage:** [openfeature.dev#1546](https://github.com/open-feature/openfeature.dev/pull/1546) adds ConfigDirector entries for Java, .NET, Python, Dart, Kotlin, and Swift, while [openfeature.dev#1485](https://github.com/open-feature/openfeature.dev/pull/1485) and [openfeature.dev#1484](https://github.com/open-feature/openfeature.dev/pull/1484) add Flaghoist and Pydantic Logfire as OFREP APIs.
- **Repository-local guidance for AI-assisted contributions is under discussion:** [community#573](https://github.com/open-feature/community/issues/573) proposes adopting `AGENTS.md` across OpenFeature repositories, with toolchain-specific contribution and testing instructions.
- **Community membership maintenance continued:** [community#578](https://github.com/open-feature/community/pull/578) moved a maintainer to emeritus status, and [community#579](https://github.com/open-feature/community/pull/579) added a new organization member.
