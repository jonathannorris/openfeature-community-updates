# OpenFeature Community Update: Jul 30 to Aug 13, 2026

_A biweekly digest of the most notable pull requests, issues, and discussions across the [open-feature](https://github.com/open-feature) org._

## TL;DR

- **Protocol ADR-0009 amended and shipped:** [protocol#80](https://github.com/open-feature/protocol/pull/80) (merged) ties the OFREP static-context cache key to base URL, auth, and bound domain to prevent cross-tenant collisions; [js-sdk-contrib#1569](https://github.com/open-feature/js-sdk-contrib/pull/1569) (merged) implements it in the OFREP web provider with a migrated v2 cache schema.
- **Numeric coercion contract, third edition running:** [flagd#1996](https://github.com/open-feature/flagd/issues/1996), [flagd-schemas#219](https://github.com/open-feature/flagd-schemas/issues/219), and [dotnet-sdk-contrib#709](https://github.com/open-feature/dotnet-sdk-contrib/issues/709) remain open; the coordinated breaking change rejects lossy fractional-to-integer truncation across gRPC, OFREP, and in-process paths.
- **Hashing consistency spreads to Java and Go:** [java-sdk-contrib#1831](https://github.com/open-feature/java-sdk-contrib/pull/1831) (open) moves flagd-core fractional targeting to canonical CBOR encoding plus MurmurHash3 bucketing; [go-sdk-contrib#932](https://github.com/open-feature/go-sdk-contrib/pull/932) (open) adds matching test-framework support, both following on from flagd's own hashing rewrite.
- **flagd OFREP still growing:** SSE push support ([flagd#2012](https://github.com/open-feature/flagd/pull/2012), XL, still in review) is joined by new fixes for stale-value signaling ([flagd#2017](https://github.com/open-feature/flagd/pull/2017)) and missing OFREP impression metrics ([flagd#2015](https://github.com/open-feature/flagd/issues/2015)/[#2016](https://github.com/open-feature/flagd/pull/2016)).
- **Multi-provider support build-out continues in Java, requested in Python:** [java-sdk#2003](https://github.com/open-feature/java-sdk/pull/2003), [#2004](https://github.com/open-feature/java-sdk/pull/2004), [#2005](https://github.com/open-feature/java-sdk/pull/2005) (all open) round out comparison strategy, aggregated child-provider state, and per-child hooks; [python-sdk#511](https://github.com/open-feature/python-sdk/issues/511) asks for the same capability.

## Spec & Protocol

### Shipped

- **[protocol#80](https://github.com/open-feature/protocol/pull/80) (merged): OFREP cache-key ADR amendment.** Fixes a gap in the static-context local-persistence ADR: the persisted cache key now includes the OFREP base URL, auth credential, and bound domain, not just the targeting key, closing a cross-tenant/cross-domain cache-collision risk surfaced from [js-sdk-contrib#1566](https://github.com/open-feature/js-sdk-contrib/issues/1566).

### Proposals to watch

- **Numeric coercion contract, still open three editions running:** [flagd#1996](https://github.com/open-feature/flagd/issues/1996), [flagd-schemas#219](https://github.com/open-feature/flagd-schemas/issues/219), [dotnet-sdk-contrib#709](https://github.com/open-feature/dotnet-sdk-contrib/issues/709). A coordinated breaking release (`feat!`) across flagd-core and every flagd provider, rejecting non-zero fractional truncation instead of silently coercing it, and capping numeric flag variants at the IEEE-754 safe-integer range.
- **Hashing consistency (canonical CBOR + MurmurHash3 bucketing):** [flagd#2011](https://github.com/open-feature/flagd/pull/2011) and the new targeting-metadata ADR at [flagd#2013](https://github.com/open-feature/flagd/pull/2013) remain in review, now joined by companion implementations in [java-sdk-contrib#1831](https://github.com/open-feature/java-sdk-contrib/pull/1831) and [go-sdk-contrib#932](https://github.com/open-feature/go-sdk-contrib/pull/932).
- **Spec v0.9.0 compliance sweep continues:** the tracking epics opened across 11 SDKs are landing sub-tasks (e.g. [dotnet-sdk#798](https://github.com/open-feature/dotnet-sdk/issues/798) spec submodule pin, [#799](https://github.com/open-feature/dotnet-sdk/issues/799) provider lifecycle event race, [#772](https://github.com/open-feature/dotnet-sdk/issues/772) bound-domain propagation) rather than closing out wholesale.

## Multi-provider support

A cross-SDK feature-parity push: Java is furthest along with three open PRs building out full multi-provider semantics ([java-sdk#2003](https://github.com/open-feature/java-sdk/pull/2003) `ComparisonStrategy`, [#2004](https://github.com/open-feature/java-sdk/pull/2004) draft aggregating child-provider events/state/tracking with worst-wins precedence, [#2005](https://github.com/open-feature/java-sdk/pull/2005) per-child hook execution), while [python-sdk#511](https://github.com/open-feature/python-sdk/issues/511) tracks the same request for Python.

## flagd & Operator

### flagd

- **[flagd#2012](https://github.com/open-feature/flagd/pull/2012) (open, XL): SSE support for OFREP.** ADR-0008's push channel at `/ofrep/v1/sse`, described as already proven in DevCycle/Dynatrace production use; still in review.
- **[flagd#2017](https://github.com/open-feature/flagd/pull/2017) (open): Report STALE reason on sync-source disconnect.** flagd currently keeps serving last-known-good flags silently when a sync source drops; this distinguishes stale from live evaluations. Closes [#400](https://github.com/open-feature/flagd/issues/400).
- **OFREP metrics gap:** [flagd#2015](https://github.com/open-feature/flagd/issues/2015) (bug) reports OFREP endpoints never record impression/reason metrics; [flagd#2016](https://github.com/open-feature/flagd/pull/2016) (open) fixes it.
- **Noisy error logging on absent comparison properties:** [flagd#2018](https://github.com/open-feature/flagd/issues/2018) and [flagd#2019](https://github.com/open-feature/flagd/pull/2019) (open) demote a full ERROR stack trace to debug-level when `starts_with`/`ends_with` targeting hits an absent property.
- **[flagd#1997](https://github.com/open-feature/flagd/issues/1997) (closed, 4 comments): inconsistent DISABLED-flag rollout flagged by the community.** flagd 0.16.0's "DISABLED is a successful evaluation" spec-alignment change wasn't uniformly implemented across provider SDKs, and the release notes undersold how breaking it was; a signal that spec-alignment rollouts need tighter cross-repo coordination.
