## Spec & Protocol

### Shipped
- **[protocol#82](https://github.com/open-feature/protocol/pull/82): ADR-0008 SSE wire format amendment (merged Jul 21).** The original ADR mandated a specific SSE envelope that conflicted with vendors like Ably, whose payloads wrap data in an extra layer (`data.data`). The amendment relaxes this: providers may implement custom deserialization as long as the output conforms to the expected schema. Approved by jonathannorris, lukas-reining, and toddbaert.

### Proposals to watch
- **[spec#405](https://github.com/open-feature/spec/pull/405): Code Readiness hook** remains open. The Go implementation merged this period ([go-sdk-contrib#904](https://github.com/open-feature/go-sdk-contrib/pull/904), released as v0.1.1); Java and other SDK implementations are still in review.

## Cross-SDK: SSE Provider Compatibility

## SDKs & Providers

- **[go-sdk-contrib#926](https://github.com/open-feature/go-sdk-contrib/issues/926) (new, high severity):** rgellis filed a detailed regression report: the flagd in-process Go provider only launches `handleEvents()` on the `ProviderReady` path of `Init`. If flagd is unreachable at startup, the event channel has no consumer for the life of the process. When flagd reconnects, `processSyncData` blocks indefinitely trying to publish `PROVIDER_READY` into the full channel; all subsequent sync payloads are dropped and the ruleset freezes permanently. `Shutdown()` also deadlocks. Affects any long-lived Go process started during a flagd outage.
- **[dotnet-sdk#787](https://github.com/open-feature/dotnet-sdk/pull/787) (merged Jul 21):** Fixes provider initialization and shutdown never running on `WebHost`/`WebHostBuilder` hosts that implement only `IHostedService` (not `IHostedLifecycleService`). The fix detects whether `StartingAsync` was ever called and falls back to `StartAsync`. Closes dotnet-sdk#773; approved by benjiro and kylejuliandev.
- **[go-sdk-contrib#902](https://github.com/open-feature/go-sdk-contrib/pull/902) (merged Jul 22):** Flipt Go provider now supports environment-aware flag evaluation via a new `Environment` config field and `ForEnvironment` option (defaults to `"default"`). Breaking: renames `Evaluate` to `Variant`, removes `GetFlag` from the Service interface, updates auth API (`ClientTokenProvider` to `ClientAuthenticationProvider`). Reviewed by beeme1mr and Flipt maintainer markphelps. Closes flipt-io/flipt#6053.
- **[dotnet-sdk-contrib#626](https://github.com/open-feature/dotnet-sdk-contrib/pull/626) (merged Jul 21):** .NET flagd provider now reads `FLAGD_SYNC_PORT` for in-process resolver config, with backwards compatibility. Completes the cross-SDK FLAGD_SYNC_PORT rollout (Python landed previously).
- **[js-sdk-contrib#1582](https://github.com/open-feature/js-sdk-contrib/pull/1582) (open):** Breaking fix for the Flagsmith JS provider: missing flags now return `FLAG_NOT_FOUND` instead of silently resolving with the default value and a `DEFAULT`/`STATIC` reason. Approved by aepfli and lukas-reining; awaiting Flagsmith maintainer review.
- **[js-sdk-contrib#1575](https://github.com/open-feature/js-sdk-contrib/pull/1575) (merged Jul 15):** New Azure App Configuration provider for JS (wilqq), released as v0.1.1.
- **[openfeature.dev#1411](https://github.com/open-feature/openfeature.dev/pull/1411) (merged Jul 17):** Flagsmith Kotlin provider added to the ecosystem (emyller).
- **[openfeature.dev#1415](https://github.com/open-feature/openfeature.dev/pull/1415) (open, Jul 22):** ConfigDirector JS providers (server and client) submitted by abeiderman; awaiting review. · **[openfeature.dev#1412](https://github.com/open-feature/openfeature.dev/pull/1412) (open, Jul 19):** feat.so JS (browser and server) and Dart providers submitted.
- **[php-sdk#180](https://github.com/open-feature/php-sdk/pull/180) (open, Jul 22):** Adds `getMetadata()`/`setMetadata()` to `EvaluationDetails` and `ResolutionDetails`, implementing spec requirements 1.4.14 and 2.2.9.
