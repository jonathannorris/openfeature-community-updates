# OpenFeature Community Update: Aug 6 to Aug 20, 2026

_A biweekly digest of the most notable pull requests, issues, and discussions across the [open-feature](https://github.com/open-feature) org._

## TL;DR

- **flagd retry timing is being aligned across SDKs:** [flagd#2027](https://github.com/open-feature/flagd/issues/2027) identifies a default backoff and stale-grace mismatch, with JavaScript and Java fixes in flight and tracking issues across more providers.
- **The Dart static-context SDK moved from design to beta code:** [dart-server-sdk#147](https://github.com/open-feature/dart-server-sdk/pull/147) merged the pure-Dart client, while [#148](https://github.com/open-feature/dart-server-sdk/pull/148) prepares its promotion.
- **flagd-proxy has a serious onboarding-order bug:** [flagd#2030](https://github.com/open-feature/flagd/issues/2030) reports subscriptions that wedge until a shared proxy restart, and [#2031](https://github.com/open-feature/flagd/pull/2031) proposes the watcher fix.
- **Protocol and specification discussions are widening:** [protocol#83](https://github.com/open-feature/protocol/issues/83) examines cache-ordering races, while [spec#390](https://github.com/open-feature/spec/issues/390) develops a provider-neutral distribution and observability model.
- **Project leadership expanded:** [community#567](https://github.com/open-feature/community/pull/567) through [#570](https://github.com/open-feature/community/pull/570) promote new approvers, a Go SDK maintainer, and a Technical Committee nominee.

## Spec & Protocol
### Shipped

- **The legacy flagd evaluation migration reached an implementation milestone:** [php-sdk-contrib#176](https://github.com/open-feature/php-sdk-contrib/pull/176) merged opt-in `flagd.evaluation.v2` support. It uses explicit field presence to distinguish absent values and preserves a caller's default when no default variant exists, providing the provider-side follow-through on the deprecation proposal in [flagd-schemas#227](https://github.com/open-feature/flagd/pull/227) covered previously.
- **Swift reason values now match specification literals:** [swift-sdk#125](https://github.com/open-feature/swift-sdk/pull/125) merged the change from Swift case names such as `staticReason` to portable values such as `STATIC`. Enum call sites are unaffected, but code comparing raw strings must account for the breaking change.

### Proposals to watch

- **OFREP cache validation may need ordering information:** [protocol#83](https://github.com/open-feature/protocol/issues/83) describes how ETag-only validation can accept an out-of-order configuration and cause an unintended rollback. It proposes an optional `Last-Modified` signal as defense in depth.
- **A write API could make OFREP useful to AI tooling:** [protocol#73](https://github.com/open-feature/protocol/issues/73) asks whether OFREP should standardize flag creation, updates, and deletion, including the authorization boundary for agents, IDEs, and MCP integrations.
- **Distribution is being considered beyond per-evaluation telemetry:** [spec#390](https://github.com/open-feature/spec/issues/390), with ten comments, proposes a neutral inventory model for flag sets, versions, variants, targeting, and observability that can be emitted by management systems, sync services, or providers.

## flagd retry and lifecycle alignment

- **Default reconnect timing is producing spurious state transitions:** [flagd#2027](https://github.com/open-feature/flagd/issues/2027) reports that the default retry backoff can exceed the stale grace period, causing Java, Go, and JavaScript providers to emit `ERROR` before recovering to `READY`. [js-sdk-contrib#1603](https://github.com/open-feature/js-sdk-contrib/pull/1603) and [java-sdk-contrib#1835](https://github.com/open-feature/java-sdk-contrib/pull/1835) correct the defaults, with coordinated tracking in [dotnet-sdk-contrib#730](https://github.com/open-feature/dotnet-sdk-contrib/issues/730), [python-sdk-contrib#408](https://github.com/open-feature/python-sdk-contrib/issues/408), and [go-sdk-contrib#936](https://github.com/open-feature/go-sdk-contrib/issues/936).

## flagd & Operator
### flagd

- **A normal service onboarding order can permanently wedge a proxy target:** [flagd#2030](https://github.com/open-feature/flagd/issues/2030) reports that subscribing before a FeatureFlag exists leaves clients without data after the resource is created, and only restarting the cluster-wide proxy recovers it. [flagd#2031](https://github.com/open-feature/flagd/pull/2031) rebuilds a multiplexer whose watcher has stopped and adds regression coverage for the related process-crash path.

## SDKs & Providers

- **The Dart client beta now has a complete first implementation:** [dart-server-sdk#147](https://github.com/open-feature/dart-server-sdk/pull/147) adds synchronous typed evaluation, immutable static context, lifecycle events, domain bindings, hooks, tracking, and an in-memory provider as an independent pure-Dart package. [dart-server-sdk#148](https://github.com/open-feature/dart-server-sdk/pull/148) keeps the promotion draft until prerelease publication and provider validation gates are complete.
- **Java's multi-provider support is being completed in three coordinated PRs:** [java-sdk#2003](https://github.com/open-feature/java-sdk/pull/2003) adds parallel comparison strategies, [java-sdk#2004](https://github.com/open-feature/java-sdk/pull/2004) aggregates child state, events, and tracking, and [java-sdk#2005](https://github.com/open-feature/java-sdk/pull/2005) executes child-provider hooks around evaluations.
- **Swift is adding the missing in-memory provider:** [swift-sdk#126](https://github.com/open-feature/swift-sdk/pull/126) proposes configuration replacement and per-flag updates, context-aware resolution, provider events, strict type checking, and thread-safe access, backed by 40 new tests.
- **Rust may gain a non-blocking evaluation path:** [rust-sdk#141](https://github.com/open-feature/rust-sdk/issues/141) proposes synchronous client and provider APIs alongside the existing async surface for in-memory and locally cached providers.
