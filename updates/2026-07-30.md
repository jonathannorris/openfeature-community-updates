# OpenFeature Community Update: Jul 16 to Jul 30, 2026

_A biweekly digest of the most notable pull requests, issues, and discussions across the [open-feature](https://github.com/open-feature) org._

## TL;DR

- **Spec v0.9.0 compliance wave:** Todd filed tracking issues against all 11 major SDKs ([go-sdk#526](https://github.com/open-feature/go-sdk/issues/526), [js-sdk#1441](https://github.com/open-feature/js-sdk/issues/1441), [java-sdk#1999](https://github.com/open-feature/java-sdk/issues/1999), and 8 more) for the two remaining v0.9.0 requirements: passing the bound domain to `provider.initialize` and hook data (spec 4.6).
- **Domain-scoped binding shipped in JS and Java:** Both SDKs merged support for passing the bound domain into `provider.initialize` ([js-sdk#1433](https://github.com/open-feature/js-sdk/pull/1433), [java-sdk#1982](https://github.com/open-feature/java-sdk/pull/1982)); releases core 1.12.0, web-sdk 1.10.0, server-sdk 1.23.0, and java-sdk 1.22.0 followed.
- **Provider conformance TCK proposed:** [spec#417](https://github.com/open-feature/spec/issues/417) opens a tracking discussion for a language-agnostic Gherkin-based conformance suite; a Java POC draft ([java-sdk-contrib#1830](https://github.com/open-feature/java-sdk-contrib/pull/1830)) already uncovers real spec violations in providers.
- **flagd: multiple reliability fixes in a burst:** readyz stuck when multiple gRPC syncs were used ([flagd#1985](https://github.com/open-feature/flagd/pull/1985)), file watcher going stale after delete-and-restore ([flagd#2001](https://github.com/open-feature/flagd/pull/2001)), and a race in the shared readiness state ([flagd#2006](https://github.com/open-feature/flagd/pull/2006)) all merged this window.
- **[js-sdk-contrib#1583](https://github.com/open-feature/js-sdk-contrib/pull/1583) merged:** The optional `parseSseMessage` hook for the OFREP JS provider landed (paired with protocol#82 from last edition), enabling Ably-style integrations without behavior change for standard deployments.

## Spec & Protocol

### Shipped

- **[spec#408](https://github.com/open-feature/spec/pull/408): Clarifications on event-driven status (merged Jul 16).** Follow-on to the lifecycle overhaul in spec#385: clarifies the ordering of lifecycle events relative to `initialize`, notes that spontaneous provider events can exist independently of lifecycle methods, and recommends coupling lifecycle and event interfaces when both are implemented.
- **[protocol#82](https://github.com/open-feature/protocol/pull/82) (merged Jul 21, noted in previous edition).** ADR-0008 SSE wire-format amendment allowing custom deserialization for non-standard vendor envelopes. Paired implementation [js-sdk-contrib#1583](https://github.com/open-feature/js-sdk-contrib/pull/1583) merged this window.

### Proposals to watch

- **[spec#417](https://github.com/open-feature/spec/issues/417): Cross-language conformance suite for OpenFeature providers (new, Jul 27).** A major initiative proposing canonical Gherkin feature files, a control API, and a standard flag set living in the spec repo, with each SDK packaging its own runner. A Java POC ([java-sdk-contrib#1830](https://github.com/open-feature/java-sdk-contrib/pull/1830)) is already submitted as a draft and uncovers real spec violations. Cross-language design decisions are being tracked on the issue before anything merges.
- **Spec v0.9.0 compliance tracking issues** filed simultaneously against go-sdk, js-sdk, java-sdk, dotnet-sdk, python-sdk, php-sdk, kotlin-sdk, cpp-sdk, ruby-sdk, rust-sdk, and swift-sdk on Jul 29. The two requirements are: (1) bound domain passed to `provider.initialize`, and (2) hook data (spec 4.6). `java-sdk#1999` is noted as functionally complete, pending only a harness bump.
- **[spec#405](https://github.com/open-feature/spec/pull/405): Code Readiness hook.** The Go implementation shipped as [go-sdk-contrib#904](https://github.com/open-feature/go-sdk-contrib/pull/904) v0.1.1 this window (merged Jul 20). Java and other SDK implementations remain open.

## Cross-SDK: Domain-Scoped Provider Binding

Both JS and Java implemented the spec clauses requiring the bound domain to be passed into `provider.initialize` (1.1.2.2, 2.4.1) and a `domainScoped` flag that rejects multi-domain binding (2.4.3, 1.1.8.1):

- **[js-sdk#1433](https://github.com/open-feature/js-sdk/pull/1433) (merged Jul 27):** JS core 1.12.0, web-sdk 1.10.0, server-sdk 1.23.0 released Jul 28. The motivation is unblocking OFREP static-context providers that need the domain at init time to scope per-domain cache keys.
- **[java-sdk#1982](https://github.com/open-feature/java-sdk/pull/1982) (merged Jul 28):** java-sdk 1.22.0 released Jul 29.

## flagd & Operator

### flagd

A cluster of reliability fixes shipped this window:

- **[flagd#1985](https://github.com/open-feature/flagd/pull/1985) (merged Jul 24): readyz never true when multiple gRPC syncs are configured.** A package-level `sync.Once` was shared across all `grpc.Sync` instances, so only the first sync to connect ever set `ready = true`. Any additional gRPC sync in the process remained permanently not-ready. Significant correctness bug for multi-source flagd setups.
- **[flagd#2001](https://github.com/open-feature/flagd/pull/2001) (merged Jul 20): file watcher stale after delete-and-restore.** Fixes the file watcher going permanently stale when the watched flag file was deleted and immediately restored (confirmed on Windows with Ctrl+Z undo). Closes #1876.
- **[flagd#2006](https://github.com/open-feature/flagd/pull/2006) (merged Jul 27): synchronize readiness state.** Fixes unsynchronized read/write of the `ready` flag across grpc, blob, and http sync types (issue #2004 filed and fixed the same week).
- **[flagd#1999](https://github.com/open-feature/flagd/pull/1999) (merged Jul 16): configurable gRPC keepalive enforcement on sync server.** Adds `EnforcementPolicy.MinTime` and `PermitWithoutStream` to the flagd sync gRPC server, fixing `GOAWAY ENHANCE_YOUR_CALM` disconnects on long-lived `SyncFlags` streams. · **[flagd#1991](https://github.com/open-feature/flagd/pull/1991) (merged Jul 20):** ETag and content-hash support for blob and HTTP syncs prevents spurious change events when source content is identical.
- **[flagd-testbed#380](https://github.com/open-feature/flagd-testbed/pull/380) (merged Jul 30):** New Gherkin scenarios for the Fractional Non-String Rand Units ADR (CBOR normalization, non-string attribute handling in fractional targeting).

### Operator

- **[open-feature-operator#852](https://github.com/open-feature/open-feature-operator/pull/852):** Exposes the flagd sync-server keepalive settings (`keepAliveMinTime`, `keepAlivePermitWithoutStream`) on `FeatureFlagSource`, pairing the flagd#1999 server-side changes at the Kubernetes operator level. Still in review.

## SDKs & Providers

- **[go-sdk-contrib#926](https://github.com/open-feature/go-sdk-contrib/issues/926):** The flagd in-process Go provider event-pump deadlock (filed last edition) remains open with no fix PR yet. The bug affects any long-lived Go process started while flagd is unreachable at startup.
- **[js-sdk-contrib#1583](https://github.com/open-feature/js-sdk-contrib/pull/1583) (merged Jul 27):** Adds optional `parseSseMessage` to the OFREP JS provider for custom SSE deserialization (Ably-style integrations), with no behavior change for standard deployments. Paired with protocol#82 (merged last edition).
- **[js-sdk#1440](https://github.com/open-feature/js-sdk/pull/1440) (open):** Fixes a race condition in the web SDK where `wrapper.status = READY` was set per-callback instead of per-transition, allowing overlapping `setContext` calls to settle the provider to READY prematurely.
- **[js-sdk-contrib#1589](https://github.com/open-feature/js-sdk-contrib/pull/1589) (open):** The flagd JS provider was reconnecting after a deliberate disconnect; fix prevents reconnection when the disconnect is intentional.
- **[rust-sdk-contrib#153](https://github.com/open-feature/rust-sdk-contrib/pull/153) (merged Jul 29):** The flagd Rust provider now makes the rustls crypto backend selectable (`tls-ring` is default, `tls-aws-lc` is opt-in), fixing a panic when the consumer's dependency graph also includes `aws-lc-rs` (e.g., AWS SDK).
- **[dotnet-sdk-contrib#699](https://github.com/open-feature/dotnet-sdk-contrib/pull/699) (merged Jul 28):** Adds `RetryBackoffMs` and `RetryBackoffMaxMs` to the flagd .NET provider's stream reconnection config; flagd provider 0.7.3 released.
- **[cpp-sdk#108](https://github.com/open-feature/cpp-sdk/pull/108) (merged Jul 16):** Fixes a TOCTOU race in `ClientAPI::EvaluateFlag` under concurrent provider swaps by retrieving the `FeatureProviderStatusManager` in a single locked operation.
- **[js-sdk-contrib#1582](https://github.com/open-feature/js-sdk-contrib/pull/1582):** Flagsmith JS provider `FLAG_NOT_FOUND` correctness fix remains open from last edition. · **[php-sdk#180](https://github.com/open-feature/php-sdk/pull/180):** `getMetadata`/`setMetadata` on `EvaluationDetails` and `ResolutionDetails` also still open.
- **New ecosystem entries:** Featureflip ([openfeature.dev#1410](https://github.com/open-feature/openfeature.dev/pull/1410), merged Jul 17) and Switchbox ([openfeature.dev#1409](https://github.com/open-feature/openfeature.dev/pull/1409), merged Jul 17) providers added to the ecosystem. Rollgate JS provider ([openfeature.dev#1421](https://github.com/open-feature/openfeature.dev/pull/1421)) is open and awaiting review. · ConfigDirector ([openfeature.dev#1415](https://github.com/open-feature/openfeature.dev/pull/1415)) and feat.so ([openfeature.dev#1412](https://github.com/open-feature/openfeature.dev/pull/1412)) provider entries from last edition remain open.
