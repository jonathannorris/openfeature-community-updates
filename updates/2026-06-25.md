## Spec & Protocol

### Proposals to watch
- **[spec#393](https://github.com/open-feature/spec/pull/393): Supply the bound domain to provider initialization.** Opened Jun 18 and in final review at the close of the window after 16 reviews. Providers would receive the `domain` they are bound to in `initialize`, so provider-level persistent caches (such as the OFREP web provider's local persistence) could partition state and stop colliding across domains.
- **[protocol#80](https://github.com/open-feature/protocol/pull/80): Amend ADR 0009 to tie the cache key to the OFREP resource** (27 reviews, in review). The persisted static-context cache key would include the bound domain, OFREP base URL, and auth credential alongside `targetingKey`, rather than leaving collision avoidance to an application-supplied prefix. Related: [js-sdk-contrib#1566](https://github.com/open-feature/js-sdk-contrib/pull/1566) proposes keying the OFREP web cache on base URL plus evaluation context.
- **[spec#385](https://github.com/open-feature/spec/pull/385): Provider state ownership via events** (in review). Keeps provider state in the SDK but derives it from provider-emitted events, addressing the multi-threaded lifecycle race in [spec#365](https://github.com/open-feature/spec/issues/365). The earlier alternative, [spec#380](https://github.com/open-feature/spec/pull/380), was closed in its favor on Jun 18 after its author kept running into TOCTOU issues with synthetic events.
- **[spec#390](https://github.com/open-feature/spec/issues/390): Flag distribution layer & observability** (10 comments, open). Discussion this window clarified the goal as standardizing an observable signal for the flag inventory, likely via OpenTelemetry semantic conventions rather than new API, and raised AI agents as consumers that need the inventory before acting.

## Isolated API instances

Umbrella tracking issue: [spec#374](https://github.com/open-feature/spec/issues/374), implementing spec section 1.8 (independent, non-singleton API instances with their own providers, hooks, context, and events).

**Landed or released this window:** [go-sdk#492](https://github.com/open-feature/go-sdk/pull/492) · [java-sdk#1928](https://github.com/open-feature/java-sdk/pull/1928) (shipped in Java SDK 1.21.0) · [kotlin-sdk#243](https://github.com/open-feature/kotlin-sdk/pull/243) (breaking) · [dotnet-sdk#760](https://github.com/open-feature/dotnet-sdk/pull/760) (DI registration on the isolated API, released in .NET SDK 2.14.0).

**Follow-ups:** [go-sdk#511](https://github.com/open-feature/go-sdk/pull/511) exports `EvaluationAPI`, removes deprecated `GetApiInstance()`/`SetLogger()`, and replaces `SetNamedProvider*` and `GetNamedClient` with `WithDomain()`-style options (8 comments). Related shutdown cleanup: Java now clears hooks, context, and propagator on shutdown per spec 1.6.2 ([java-sdk#1936](https://github.com/open-feature/java-sdk/pull/1936)), and [js-sdk#1430](https://github.com/open-feature/js-sdk/pull/1430) proposes the same for JS ([js-sdk#1374](https://github.com/open-feature/js-sdk/issues/1374)).

**Remaining:** JS ([js-sdk#1373](https://github.com/open-feature/js-sdk/issues/1373)) · Python ([python-sdk#584](https://github.com/open-feature/python-sdk/issues/584)) · Swift ([swift-sdk#115](https://github.com/open-feature/swift-sdk/issues/115)).

## flagd & Operator

### flagd
- **[dotnet-sdk-contrib#647](https://github.com/open-feature/dotnet-sdk-contrib/pull/647): FILE resolver for the .NET flagd provider.** Reads flag definitions from a local file, validates them against the schema, and live-reloads on change, with no flagd connection required (closes the long-standing [dotnet-sdk-contrib#308](https://github.com/open-feature/dotnet-sdk-contrib/issues/308)).
- **[dotnet-sdk-contrib#685](https://github.com/open-feature/dotnet-sdk-contrib/pull/685): in-process resolver stopped applying updates after the initial sync.** A synchronously completed `TaskCompletionSource` ran caller continuations on the stream loop thread; fixed and released in Flagd provider 0.7.1 ([dotnet-sdk-contrib#684](https://github.com/open-feature/dotnet-sdk-contrib/issues/684)). Also [dotnet-sdk-contrib#697](https://github.com/open-feature/dotnet-sdk-contrib/pull/697) fixes an event stream hot-spin.
- **[go-sdk-contrib#903](https://github.com/open-feature/go-sdk-contrib/pull/903): data race in the Go flagd in-process service**, caused by re-assigning a `sync.Once` to signal readiness after reconnects (opened Jun 24).
- **[flagd#1980](https://github.com/open-feature/flagd/pull/1980): server ReadTimeouts and security dependency updates** (in review), resolving 28 of 33 open Dependabot alerts.
- **Testing:** the Java flagd provider's e2e suite is ~75% faster via a pre-warmed container pool and parallel scenarios ([java-sdk-contrib#1752](https://github.com/open-feature/java-sdk-contrib/pull/1752)); test-harness bumped to v3.8.0 ([java-sdk-contrib#1817](https://github.com/open-feature/java-sdk-contrib/pull/1817)); a new testbed suite for non-string attributes in fractional evaluation ([flagd-testbed#378](https://github.com/open-feature/flagd-testbed/issues/378)).

## SDKs & Providers

- **[dotnet-sdk#755](https://github.com/open-feature/dotnet-sdk/pull/755): evaluation traces in .NET** (40 reviews). Emits a trace per flag evaluation following the OpenTelemetry feature-flag semantic conventions, distinct from the existing `TraceEnricherHook`; shipped in .NET SDK 2.14.0 and resolves [dotnet-sdk#595](https://github.com/open-feature/dotnet-sdk/issues/595).
- **New providers and backends:** Unleash for .NET ([dotnet-sdk-contrib#652](https://github.com/open-feature/dotnet-sdk-contrib/pull/652), docs in [openfeature.dev#1399](https://github.com/open-feature/openfeature.dev/pull/1399)); GCP Parameter Manager support in the Java GCP provider ([java-sdk-contrib#1808](https://github.com/open-feature/java-sdk-contrib/pull/1808)); environment-aware evaluation for the Go Flipt provider ([go-sdk-contrib#902](https://github.com/open-feature/go-sdk-contrib/pull/902), in review). The Java Optimizely provider reached 1.0.0.
- **Thread safety:** Python SDK fixes ([python-sdk#614](https://github.com/open-feature/python-sdk/pull/614), 6 comments, in review); C++ fixes a race between status check and provider lookup ([cpp-sdk#108](https://github.com/open-feature/cpp-sdk/pull/108), in review).
- **C++ SDK 0.1.0:** provider evaluation now returns `absl::StatusOr` so provider errors no longer crash the caller (requirement 1.4.10, breaking, [cpp-sdk#97](https://github.com/open-feature/cpp-sdk/pull/97)), plus evaluation correctly blocked for ERROR and STALE providers ([cpp-sdk#96](https://github.com/open-feature/cpp-sdk/pull/96)).
- **Java performance:** a series of allocation reductions for empty contexts, metadata, and hook merging from a single contributor ([java-sdk#1956](https://github.com/open-feature/java-sdk/pull/1956) · [#1969](https://github.com/open-feature/java-sdk/pull/1969) · [#1972](https://github.com/open-feature/java-sdk/pull/1972) · [#1975](https://github.com/open-feature/java-sdk/pull/1975)). Java SDK 1.21.0 also includes per-provider error propagation in multi-provider strategies ([java-sdk#1901](https://github.com/open-feature/java-sdk/pull/1901)).
- **JS:** server-sdk 1.22.0 and web-sdk 1.9.0 expose SDK identity on client metadata ([js-sdk#1376](https://github.com/open-feature/js-sdk/pull/1376)); React SDK 1.4.1 stops re-registering event handlers on every parent re-render ([js-sdk#1420](https://github.com/open-feature/js-sdk/pull/1420)).
- **Rust contrib:** workspace restructure and per-crate release lanes for the flagd family ([rust-sdk-contrib#118](https://github.com/open-feature/rust-sdk-contrib/pull/118), [rust-sdk-contrib#130](https://github.com/open-feature/rust-sdk-contrib/pull/130)).
