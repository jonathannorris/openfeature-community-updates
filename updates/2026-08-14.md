# OpenFeature Community Update: Jul 31 to Aug 14, 2026

_A biweekly digest of the most notable pull requests, issues, and discussions across the [open-feature](https://github.com/open-feature) org._

## TL;DR

- **flagd reliability work landed:** [flagd#2016](https://github.com/open-feature/flagd/pull/2016) now records OFREP evaluation metrics, while [flagd#2024](https://github.com/open-feature/flagd/pull/2024) and [flagd#2025](https://github.com/open-feature/flagd/pull/2025) close separate concurrency hazards.
- **Protocol cleanup is moving forward:** [flagd-schemas#224](https://github.com/open-feature/flagd-schemas/pull/224) proposes safe-integer bounds for numeric variants, and [flagd-schemas#227](https://github.com/open-feature/flagd-schemas/pull/227) proposes deprecating the legacy evaluation API.
- **Static-context SDK design is spreading:** [dart-server-sdk#117](https://github.com/open-feature/dart-server-sdk/issues/117) proposes a pure Dart client SDK, while [rust-sdk#140](https://github.com/open-feature/rust-sdk/pull/140) adds per-hook evaluation state.
- **Provider integrations continue to broaden:** the catalog added Featurevisor, Octopus Deploy, Superposition, Optimizely, Firebase Remote Config, Azure App Configuration, Bucketeer, PostHog, Pendo, and CloudBees providers across multiple languages.
- **Stream recovery is getting more robust:** [python-sdk-contrib#391](https://github.com/open-feature/python-sdk-contrib/pull/391) shipped reconnect backoff, and [js-sdk-contrib#1596](https://github.com/open-feature/js-sdk-contrib/pull/1596) plus [#1597](https://github.com/open-feature/js-sdk-contrib/pull/1597) address graceful stream closure and disabled-polling SSE recovery.

## Spec & Protocol
### Shipped

- **OFREP evaluation metrics are now recorded per flag:** [flagd#2016](https://github.com/open-feature/flagd/pull/2016) merged the fix for single and bulk OFREP responses, preserving each result's key, variant, reason, and error data.

### Proposals to watch

- **Numeric coercion is gaining a schema-level guardrail:** [flagd-schemas#224](https://github.com/open-feature/flagd-schemas/pull/224) adds the IEEE-754 safe-integer range to numeric variants and boundary fixtures. It is the concrete schema piece of the still-open coordinated contract in [flagd#1996](https://github.com/open-feature/flagd/issues/1996), [flagd-schemas#219](https://github.com/open-feature/flagd-schemas/issues/219), and [dotnet-sdk-contrib#709](https://github.com/open-feature/dotnet-sdk-contrib/issues/709).
- **Legacy evaluation APIs are being retired:** [flagd-schemas#226](https://github.com/open-feature/flagd-schemas/issues/226) and [#227](https://github.com/open-feature/flagd-schemas/pull/227) propose marking `flagd/evaluation/v1` deprecated once the remaining provider migration, tracked in [php-sdk-contrib#176](https://github.com/open-feature/php-sdk-contrib/pull/176), is complete. [flagd#1088](https://github.com/open-feature/flagd/issues/1088) tracks removal of the older compatibility implementations.

## Static-context client SDKs

- **Dart client architecture is now under review:** [dart-server-sdk#117](https://github.com/open-feature/dart-server-sdk/issues/117) proposes a pure Dart client package with synchronous evaluation, asynchronous lifecycle reconciliation, hooks, tracking, and an explicit v0.9 conformance baseline. The accompanying architecture documentation landed in [dart-server-sdk#118](https://github.com/open-feature/dart-server-sdk/pull/118).

## flagd & Operator
### flagd

- **Two concurrency failures are fixed:** [flagd#2024](https://github.com/open-feature/flagd/pull/2024) moves Kubernetes scheme registration to package initialization to avoid concurrent map access, and [flagd#2025](https://github.com/open-feature/flagd/pull/2025) sends the initial event from the handler to avoid a disconnect race.
- **Keepalive controls are being aligned across deployments:** [flagd#2022](https://github.com/open-feature/flagd/pull/2022) adds gRPC enforcement settings to flagd-proxy, matching flagd defaults and addressing periodic `GOAWAY ENHANCE_YOUR_CALM` disconnects. The operator side is covered below.
- **Flag-set-aware telemetry is the next observability request:** [flagd#2020](https://github.com/open-feature/flagd/issues/2020) asks for the flag set ID as an OpenTelemetry metric attribute for both flagd and OFREP.

### Operator

- **FeatureFlagSource can expose keepalive settings:** [open-feature-operator#852](https://github.com/open-feature/open-feature-operator/pull/852) adds opt-in fields for minimum keepalive time and permitting pings without an active stream, emitting the corresponding environment variables without changing existing defaults.

## SDKs & Providers

- **Rust HookData is proposed for hook-scoped state:** [rust-sdk#140](https://github.com/open-feature/rust-sdk/pull/140) adds a per-hook, per-evaluation key-value store shared across `before`, `after`, `error`, and `finally`, matching the spec's Hook Data model.
- **Kotlin context refresh behavior is being corrected:** [kotlin-sdk#251](https://github.com/open-feature/kotlin-sdk/pull/251) makes every context setter call reach `onContextSet`, even when values are equal, so providers that refresh on context changes do not keep stale state.
- **flagd provider reconnect behavior improved in Python and JavaScript:** [python-sdk-contrib#391](https://github.com/open-feature/python-sdk-contrib/pull/391) adds interruptible backoff before RPC and in-process stream recreation. [js-sdk-contrib#1596](https://github.com/open-feature/js-sdk-contrib/pull/1596) handles graceful gRPC stream ends, while [#1597](https://github.com/open-feature/js-sdk-contrib/pull/1597) fixes SSE recovery when polling is disabled with a negative interval.
